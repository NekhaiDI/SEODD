# Методология: от метрик к плану работ

Как интерпретировать сводку `summary_*.json` и строить отчёт для пользователя.
Основано на методологии SEO-аудита Anthropic (knowledge-work-plugins →
marketing/seo-audit), адаптировано под метрики, которые реально собирает тулкит.

## Пороги и нормы

| Метрика | Норма | Проблема |
|---|---|---|
| title | 50–60 символов, уникальный | отсутствует; < 25 или > 70; дубли |
| meta description | 150–160 символов, уникальный | отсутствует; < 70 или > 180; дубли |
| H1 | ровно один | нет H1; несколько H1 |
| Объём текста | зависит от типа страницы | < 150 слов («тонкий» контент); для информационных страниц ориентир 300+ |
| canonical | есть и указывает на саму страницу | отсутствует; указывает на другой URL (проверить, не намеренно ли) |
| noindex | только на служебных страницах | noindex на страницах каталога/контента |
| alt у изображений | есть у всех значимых | > 30% изображений без alt |
| schema.org / OG | есть на ключевых страницах | полное отсутствие по сайту |
| Время ответа | < 500 мс в среднем | > 1000 мс в среднем |
| Битые страницы | 0 | любые 4xx/5xx во внутренней перелинковке |

## Серьёзность проблем

- **Критично** — мешает индексации или напрямую бьёт по ранжированию:
  noindex на боевых страницах, битые страницы, массовое отсутствие title.
- **Высокая** — заметный эффект: отсутствие/дубли title и description на
  значимой доле страниц, отсутствие H1, массовый «тонкий» контент.
- **Средняя** — нарушение best practices: несколько H1, отсутствие canonical,
  слишком короткие/длинные title, высокая доля изображений без alt.
- **Низкая** — точечные улучшения: отсутствие OG-тегов, отдельные страницы
  с малым текстом, длина description вне нормы.

При сравнении с конкурентами серьёзность повышается, если конкуренты в этой
метрике заметно лучше (проигрыш по фронту), и понижается, если у всех одинаково
плохо (не конкурентный разрыв, а общая гигиена).

## Структура отчёта пользователю

1. **Резюме (3–5 предложений)** — общее состояние SEO, сильная сторона сайта,
   топ-3 приоритета, вердикт: «крепкая база», «нужна работа» или «критичные
   проблемы».
2. **Сравнение с конкурентами** — 3–5 строк о том, где сайт выигрывает и
   проигрывает; таблицу целиком не пересказывать, она есть в HTML-отчёте.
3. **Проблемы по серьёзности** — таблица: проблема, сколько страниц затронуто,
   серьёзность, что делать. Примеры конкретных URL — по 2–3 на проблему,
   остальное в Excel.
4. **План работ** в двух корзинах:
   - **Быстрые победы (сделать на этой неделе)** — до 2 часов каждая:
     дописать title/description на конкретных страницах, поправить H1,
     добавить alt, закрыть служебные страницы от индексации.
   - **Стратегические задачи (планировать на квартал)** — расширение
     «тонких» страниц каталога, внедрение schema.org, ускорение сервера,
     пересмотр структуры каталога.
   Для каждого пункта: что сделать (конкретно), ожидаемый эффект
   (высокий/средний/низкий), оценка трудозатрат.
5. **Ссылки на отчёты** — абсолютные пути к HTML и Excel; предложить открыть
   HTML в браузере.

## Follow-up

После отчёта предложить продолжение (выбрать уместное):
- составить готовые title/description для проблемных страниц;
- добавить/поменять конкурентов и перезапустить сравнение;
- запустить полный прогон, если был быстрый (`--max-pages 50`);
- поставить аудит на расписание (cron / Планировщик заданий / скилл schedule);
- доработать тулкит под задачу, которой не хватает (см. extending.md).

## Ограничения тулкита (говорить честно)

- Нет данных о позициях, трафике и ключевых словах — для этого нужны
  Google Search Console / Яндекс.Вебмастер или Ahrefs/Semrush через MCP.
- Краулер видит серверный HTML: для SPA и проверки скорости использовать
  скилл `browser-verify`.
- «Домен-авторитет» и ссылочный профиль не оцениваются.
