# AI-видимость (GEO / Generative Engine Optimization)

Как интерпретировать AI-метрики тулкита и что рекомендовать. Главный сдвиг:
AI-поисковики не ранжируют страницы — они **цитируют источники**. Попасть в
цитаты ответа ассистента — новый эквивалент «первого места в выдаче».

## Три категории AI-ботов (не путать!)

Тулкит проверяет robots.txt по категориям (`seo_kit/ai_visibility.py`):

| Категория | Боты | Блокировка означает |
|---|---|---|
| **search/retrieval** | OAI-SearchBot, Claude-SearchBot, PerplexityBot, Bingbot, Googlebot, YandexBot | сайта **нет в ответах ассистентов** — критично |
| **fetch** (по запросу пользователя) | ChatGPT-User, Claude-User, Perplexity-User | ассистент не может открыть страницу, когда пользователь просит |
| **training** (обучение моделей) | GPTBot, ClaudeBot, Google-Extended, Applebot-Extended, CCBot, meta-externalagent | видимость в AI-поиске **не страдает** — осознанный выбор владельца |

Частые ошибки в чужих гайдах (не повторять):

- `GPTBot` ≠ `OAI-SearchBot`; `ClaudeBot` ≠ `Claude-SearchBot`. Блокировка
  training-бота не блокирует одноимённый поиск.
- `Google-Extended` управляет обучением Gemini, а не показом в
  AI Overviews — за AI Overviews отвечает обычный Googlebot.
- robots.txt управляет **краулингом**, а не индексацией. Чтобы страницы
  не было в выдаче — meta noindex, и при этом её нельзя Disallow'ить
  (иначе робот не увидит noindex).
- Некоторые боты (Bytespider) игнорируют robots.txt — реальная блокировка
  только на уровне WAF/CDN.

Интерпретация метрики `ai_search_bots` в сравнении: `6/6` — норма;
меньше — смотреть `ai_visibility.<site>.search_bots_blocked` в summary JSON
и чинить robots.txt (критичная проблема).

## llms.txt — честная оценка

`/llms.txt` — markdown-карта сайта для LLM (H1-заголовок, аннотация-цитата,
секции со списками ссылок). Поддержка **частичная**: Anthropic и Perplexity
учитывают при retrieval, Google для AI Overviews — нет, OpenAI не
обязывался. Рекомендовать как дешёвое улучшение с низким/неопределённым
эффектом — **не** как доказанный фактор ранжирования. Приоритет: низкий.

## Машиночитаемые факты (высокий приоритет для e-commerce)

AI-агент, отвечающий «где купить X и почём», надёжно извлекает цену и
наличие только из structured data. Метрики `pct_product_schema` /
`pct_faq_schema` в сравнении показывают, у кого каталог читается агентами:

- **Product + Offer** (цена, валюта, наличие) — на карточках товара;
- **FAQPage** — на страницах с вопросами (повышает цитируемость);
- **Organization** (контакты, адрес) — на главной/контактах;
- **BreadcrumbList** — структура каталога.

Полный список типов по каждой странице — поле `schema_types` в `data/*.json`.

## Контент, который цитируют (рекомендации в план работ)

По исследованию GEO (Princeton, KDD 2024) — эффект на видимость в ответах
генеративных движков (цифры направленные, не гарантия):

- цитирование авторитетных источников: +30–40%;
- конкретная статистика и числа: +35%;
- цитаты экспертов с атрибуцией: +30%;
- «answer-first»: прямой ответ в первом абзаце, детали ниже;
- чёткая иерархия H1→H2→H3, списки, таблицы сравнения, короткие абзацы;
- keyword stuffing — **вредит** (−10%).

## Рендеринг: AI-краулеры не исполняют JS

Большинство AI-краулеров читают только серверный HTML — ровно как наш
краулер. Если `word_count` в отчёте близок к нулю, а в браузере страница
полная — контент дорисовывается JS и **невидим для AI-поиска** (и для
нашего отчёта). Проверка: скилл `browser-verify` → сравнить `get-html`
(отрендеренный DOM) с сырым HTML. Лечение — SSR/пререндер ключевых страниц.

## Платформенные особенности

- **Claude** — использует индекс Brave Search; ценит фактологическую
  плотность и извлекаемую структуру.
- **ChatGPT** — нужен Bing-индекс; свежесть контента (обновления < 30 дней
  цитируются заметно чаще).
- **Perplexity** — уважает FAQ-разметку, индексирует PDF.
- **Google AI Overviews** — классический E-E-A-T + structured data.
- **Яндекс Нейро/Алиса** (актуально для .by/.ru) — обычный YandexBot,
  Яндекс.Вебмастер, разметка по schema.org.
